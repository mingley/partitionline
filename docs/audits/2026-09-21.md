## Reproduced consumer defects

The [diagnostic fixture](2026-09-21-consumer-probes.rs) contains five
expected-behavior tests. Four use a small loopback Kafka wire fixture; the
capped-poll test uses the existing integration mock. They exercise the
public client, not a reimplementation of its consumer algorithm.

All five fail at the audited SHA. These are deterministic semantic
reproductions, **not independent wire-conformance or live-broker results**.

| ID | Contract and observed result | Root-cause location at audited SHA | First repair |
|---|---|---|---|
| A01 | Assign offset 2; a broker returns the complete batch containing offsets 0, 1, 2. Expected `[2]`; received `[0, 1, 2]`. Restart/seek inside a batch can redeliver records before the requested position | `src/consumer.rs:2593-2634`, `apply_fetch_body`: no lower-bound check against the requested partition offset | KL03-04 |
| A02 | PID 7 aborts a transaction at offset 0, with ABORT marker 1, then commits another at offset 2, with COMMIT marker 3. `read_committed` should return `[2]`; it returns `[]` and advances past the data | `src/consumer.rs:2594-2621`: control batches are skipped without ending the aborted-PID interval; every later offset for that PID matches the first aborted offset | KL03-03 |
| A03 | One partition succeeds while another returns a retriable error. Expected `[(0, 0), (1, 0)]`; received only `[(1, 0)]`. The successfully fetched record disappears from application delivery | `src/consumer.rs:2355-2391`: successful bodies advance assignment offsets, then the retry branch discards the round-local `out` vector | KL03-02 |
| A04 | With `auto.offset.reset=None`, Fetch reports `OFFSET_OUT_OF_RANGE` and log start 10. Expected an error and unchanged position 0; received success and position 10 | `src/consumer.rs:2546-2553`: unconditional reset to log start, without consulting the policy; `Latest` needs separate coverage too | KL03-05 |
| A05 | Fetch three records with `max_poll_records=1`; process offset 0, call no-argument `commit()`, leave and rejoin. Expected remaining offsets `[1, 2]`; received `[]` | `src/consumer.rs:2640-2643,3166-3191` advances the fetch cursor before buffering excess records; `src/group.rs:1373-1388` commits that cursor instead of the delivered position | KL03-06, KL03-07 |

The independent behavioral reference for A01/A02 is Kafka 4.1.0
[`CompletedFetch`](https://github.com/apache/kafka/blob/13f70256db3c994c590e5d262a7cc50b9e973204/clients/src/main/java/org/apache/kafka/clients/consumer/internals/CompletedFetch.java#L200-L239):
it clears an aborted producer on its ABORT marker and filters records below
`nextFetchOffset`. For A04, see
[`FetchCollector`](https://github.com/apache/kafka/blob/13f70256db3c994c590e5d262a7cc50b9e973204/clients/src/main/java/org/apache/kafka/clients/consumer/internals/FetchCollector.java#L336-L360).
These are client semantic references, not a requirement to copy Java internals.

The current mock hides important shapes: `tests/common/mod.rs:5162-5220`
filters records before constructing a fetch batch and collapses returned
records into one batch. The existing transaction test commits **before**
aborting, rather than committing again after an abort. Preserve the mock's
fast feedback, but add realistic batch/control-marker and partial-failure
fixtures instead of teaching the mock to agree with broken client behavior.

## Additional verified gaps

### A06: Self-round-trips are not independent protocol oracles

`tests/protocol_oracles.rs:172-200` creates Produce responses with
`partitionline`'s encoder and reads them with its decoder. The other fixture
families follow the same approach. `matrix.json` supplies version lists and
`fixture:apache/kafka:<version>` labels, not independently generated bytes.
A matching encoder/decoder mistake can pass.

The one live test is ignored by default. `ci-protocol-oracles.sh` enables it
only with `REQUIRE_BROKER=1`; that live script path is not a required CI job.
Existing tests are useful local consistency tests, not proof of Java/broker
differential coverage. KL01-01 through KL01-08 add a source-pinned case
registry, independent fixtures, adapters and fail-closed results.

### A07: Protocol fields exist without corresponding runtime policy

The consumer calls `encode_fetch_request`, which always uses
`FetchMetadata::LEGACY` (`src/protocol/fetch.rs:1062-1082`), despite lower-level
incremental-session helpers already existing. Implement KIP-227 at the
high-level client; do not add a second wire codec.

KIP-848 heartbeats use configured `heartbeat_interval`, default 150 ms
(`src/group.rs:2149-2249`), rather than the response's
`heartbeat_interval_ms`. Share heartbeats hard-code 150 ms
(`src/share.rs:1542-1621`). With a requested interval of 5 seconds, 150 ms
would schedule about 33 times as many heartbeats before accounting for I/O.
That is a scheduling calculation, not a measured CPU cost.

Produce/fetch decode throttle fields but discard them in their runtime
response paths. Add version-aware quota scheduling and observable throttled
time, preserving deadlines and other brokers' progress. KL03-12/13 and
KL05-06 through KL05-09 cover these distinct changes.

### A08: Logical payload bounds do not establish process-memory bounds

`src/producer.rs:914-918` reserves key plus value bytes; headers, record
objects, encoded/compressed buffers and socket memory are outside that
counter. This limitation is already documented in the guide; the passing
`buffer_ownership` tests do not prove more.

Gzip/LZ4 decompression uses `read_to_end`, and snappy allocates decompressed
blocks (`src/protocol/records.rs:1620-1705`). Counts are checked **after**
decompression at `2057-2082`. There is no decoded-byte budget on these paths.
The response-frame limit is not a decompression bound.

KL02 makes ownership, decoded-byte limits, error-path release, deadlines and
overload evidence separate deliverables. This audit did not run resource
exhaustion payloads or classify exploitability.

### A09: Broad API inventory is not current, complete client support

Present: produce/fetch, classic/cooperative groups, KIP-848, share APIs,
idempotence/transactions, many admin APIs, gzip/snappy/LZ4, rustls/mTLS,
PLAIN/SCRAM/OAUTHBEARER/OIDC and optional tracing.

Important remaining work:

| Surface | Audited state | Completion requirement |
|---|---|---|
| zstd | Compression ID 4 is unsupported in `src/protocol/records.rs`; no encoder or decoder | Separate bounded decode, encode and independent interop; approve backend/dependency policy first |
| GSSAPI/Kerberos | No mechanism implementation | Explicit opt-in/backend decision, implementation and credential-lifecycle proof before claiming enterprise-auth completeness |
| Incremental Fetch / quota policy | Codec helpers/fields, not full runtime behavior | KL05 runtime tasks and scale evidence |
| Current broker generations | CI covers 3.9.1 and 4.1.0 | Add named current-release cells; retain older cells only as an explicit compatibility policy |
| Newer API versions | Runtime caps include Produce 12, Fetch 17, ListOffsets 10, ShareFetch 1 | Inventory differences and implement needed fields/behavior; lower-version negotiation alone is not a feature gap, but cannot enable new semantics |
| Extended admin | ElectLeaders, DescribeQuorum and Raft-voter operations are names in the key catalog, not implemented high-level methods | Explicit full-admin scope and small API-specific codec/runtime tasks |
| Schema Registry | `partitionline-schema` is `publish=false`, workspace-excluded, with only a five-byte framing scaffold | Registry/cache and format-specific adapters, including Protobuf message indexes; keep ecosystem code outside the core client |
| Production qualification | No multi-broker crash-history or filled independent adopter evidence established here | Scoped histories, recovery/resource campaigns and approved rollout |

### A10: Documentation is extensive, but its strict gate is incomplete

Four rustdoc tests pass. A strict all-feature build fails:

```text
src/protocol/oidc.rs:82:
public documentation for fetch_client_credentials_token
links to private item OIDC_FETCH_ATTEMPTS
```

`scripts/ci-docs.sh` looks for the text `unresolved link`; it is not a
`-D warnings` gate. `ci.yml` has no dedicated rustdoc/doctest or Markdown
snippet/link job. `cargo test --all-targets` is not the doctest lane.

`ROADMAP`, `TODO`, `CIVILIZATION` and the long `STATUS` chronology also offer
competing starting points. The new queue has one authority; later KL07 tasks
separate tutorials, recipes, API reference and explanation, compile the
actual examples, and measure newcomer usability. Fixing the private link is
a deliberately small first task, not a documentation rewrite.

### A11: Existing measurements cannot support a universal speed claim

Preserve the historical locked produce results and the withdrawn invalid
idempotent result. Preserve the distinction between Lab A produce evidence,
unsigned this-VM fetch/latency samples, and **Suite HOLD**.

Current limitations are directly visible:

- `examples/bench_latency.rs` sequentially awaits each send, and samples only
  nonempty fetches. It is useful service-time smoke, not scheduled open-loop
  end-to-end latency through saturation.
- `lab-a-produce.sh` says C comparisons are manual. The documented
  rust-rdkafka peer drivers are standalone, not reproducibly built in this tree.
- Default produce workload is repeated 100-byte values, six partitions,
  replication one and short count-bound runs. It is not multi-host,
  skew/entropy/large-record or production-durability qualification.
- High-watermark/count equality is a necessary smoke check in the relevant
  nontransactional case, not an ID/payload/order or exactly-once oracle.
- The frozen CI latency cell measured 1,872 us p99 against a 5,000 us
  shared-runner ceiling. That passes its declared smoke budget; it is neither
  a controlled-host result nor the old 750 us local budget.

KL04 separates contract, pinned peers, load driver, correctness histories,
raw results, microbenchmarks, controlled runs, analysis and independent
reproduction. Optimize a measured bottleneck only after its semantics pass.

### A12: Exact-SHA release checks can accept a non-CI workflow

`scripts/check-main-ci.sh` first filters matching-SHA runs for `ci`, then uses
`... or match` when that list is empty. Thus a successful Release-plz run for
the right SHA can satisfy the check while CI is absent. This is a
source-confirmed gate defect, not evidence that a bad release occurred.

The canonical release workflow has gained useful checks, but
`first-publish.yml` remains manually dispatchable with a separate concurrency
group and no exact-CI gate. Its version-0.1.0 guard limits its scope; do not
misdescribe it as a general future-version publisher. `release.yml` also
serializes by tag and cancels superseded same-tag runs, not by a single global
publication lock. Retire the obsolete path and make interrupted publication
idempotent. Existing owner/local paths need the same gate, not another wrapper.

KL08-01 is the smallest urgent repair. No workflow, tag, registry secret or
published version was changed during this audit.

### A13: Recovery qualifications must follow the real reference state machine

Do not replace recovery with a blanket rule such as "every local epoch bump
is invalid." Kafka's nontransactional
[`TransactionManager`](https://github.com/apache/kafka/blob/13f70256db3c994c590e5d262a7cc50b9e973204/clients/src/main/java/org/apache/kafka/clients/producer/internals/TransactionManager.java#L641-L679)
does permit local epoch bumps, with sequence rewriting and producer-ID reset
rules. This crate's shared epoch/sequences and retained pending batches need
multi-partition, in-flight and lost-ack histories against that contract.
Transactional recovery is a separate case. KL03-08 through KL03-11 add the
proof before declaring a particular recovery mechanism correct or incorrect.

## Standards and upstream evidence boundary

"All OSS specs" needs a versioned denominator, not a badge. No single portable
Kafka-client certification executable or universal performance standard was
identified in the inspected upstream sources.

| Authority | What it establishes | What it does not establish |
|---|---|---|
| [Apache wire guide](https://kafka.apache.org/43/design/protocol/) and pinned `clients/src/main/resources/common/message` JSON | Wire fields, versions, flexible/tagged encodings and negotiation requirements | Runtime cancellation, memory bounds or throughput leadership |
| Pinned Apache Java implementation and tests | Client behavior for offsets, transactions, membership, retries and error handling | Automatic applicability of every Java-only helper/API-shape assertion |
| [Apache client system tests](https://github.com/apache/kafka/tree/26b251a451ce941d3d7a55e6487bcb7f16b5ad48/tests/kafkatest/tests/client) | Compatibility, compression, rolling upgrades, truncation, groups and share scenarios | A ready-made Rust runner; producer/consumer service adapters are required |
| [librdkafka regression suite](https://github.com/confluentinc/librdkafka/tree/9a94e11452cdeb0a844db44ee5dd01ccbe17d3ab/tests) | Independent client behavior and failure scenarios | Drop-in execution against a Rust API; C/C++-specific cases need classification |
| SASL/OAuth/TLS and codec specifications referenced by those implementations | Mechanism and format requirements | Evidence that a codec enum or successful handshake handles rotation and faults |
| Repository benchmark contract | Named comparative workloads, confidence and performance targets | An Apache-mandated performance threshold or a universal "fastest" result |

Every selected upstream case needs its source SHA/path, profile, adapter,
broker/API versions, result and artifact. Allowed dispositions are `passed`,
`failed`, `not_run`, `unsupported`, `blocked_external`, and
`not_applicable` with a reason. Missing credentials/infrastructure are
`blocked_external`, not `not_applicable`; unsupported major features remain
visible blockers for the full-feature profile. Report numerator and denominator.
Never drop a failed case or loosen its assertion to make an adapter pass.
