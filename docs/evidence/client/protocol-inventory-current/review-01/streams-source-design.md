# Bounded Streams protocol source proposal

Pending a separately claimed write set; no production edits/builds have started. New owned module `src/protocol/streams.rs`, a focused integration test file, and a new isolated Streams fixture/oracle directory. Root owns `src/protocol/mod.rs`, api_keys/header registration and feature/case registry changes. Public Admin integration must be coordinated with the sole current src/admin.rs owner. No changes to records.rs, shared buf.rs, taskbook, dependencies or default features.

## First callable capability

Implement all four API88/API89 v0 request/response codecs and public typed values, not generic opaque byte forwarding. Registration of constants/header2/header1 is necessary but cannot itself become a runtime-support claim. A later or coordinated thin caller-selected Streams client operation should use broker-negotiated v0 and GROUP coordinator lookup, actual absolute deadline/retry semantics, and return typed responses. Admin::describe_streams_groups belongs to the Admin owner; heartbeat should not be wired into ConsumerGroup or ShareConsumer state machines. A genuine server Streams coordinator is a separate task; codecs do not implement one.

Explicit version argument rejects every version except0; Kafka4.1.2's v0 is an unstable protocol and must require an explicit allowance when selected, whereas4.2.1/4.3.1 are stable. Root registration must not advertise server support from core codecs.

## Data model and wire

- Separate `StreamsGroupHeartbeatRequest/Response` and `StreamsGroupDescribeRequest/Response` types.
- Shared primitive structs Endpoint (u16 port), TaskIds (subtopology string + partition IDs), TaskOffset (subtopology, partition, i64 offset), KeyValue and TopicInfo. Distinct heartbeat topology and described topology: heartbeat adds regex and copartition sets; describe does not have those fields. Distinct response assignment, member, status and endpoint-partition mapping types. Reuse only fields whose pinned schemas are identical.
- Preserve `Option<Vec<T>>` for nullable arrays; null means unchanged in heartbeat, empty means explicit empty. Preserve nullable nested structs and nullable strings; retain raw signed values/defaults rather than silently clamping epochs, offsets or errors. MemberEpoch0 joins, -1 leaves, -2 signals static rejoin; topology is nonempty on join at the semantic layer. EndpointInformationEpoch and TopologyEpoch are distinct values.
- Kafka nullable structs use a signed one-byte presence prefix: generated writers write -1 for null and1 for present, generated readers treat negative as null. This differs from compact array/string null encoding0. Preserve the actual schema; do not encode structs as nullable compact arrays.
- All structs have flexible tagged fields. A module-local bounded tag decoder enforces ascending unique tags and total tag bytes/count before skipping unknown payloads. Unknown tags are explicitly discarded; tests distinguish semantic round-trip from byte-for-byte preservation. Canonical encoders write empty tags unless the chosen new public type explicitly retains raw tags. No changes to shared buf.rs for this policy.
- Three releases have the same reachable v0 wire shape. 4.1.2-only unused `TopicPartitions` commonStruct is not an encoded field and needs no Rust public type. Different constructor annotations do not justify wire divergence.

## Bounds before allocation

Use a module-local slice Reader with checked offsets and a caller-provided, eagerly validated positive Limits: maximum wire bytes, maximum single string bytes, total copied string bytes, maximum per-array count, aggregate elements, tagged fields/tag bytes, and decoded reservation bytes. Default bounded convenience functions can delegate to explicitly limited variants. Never allocate based solely on a count; prove checked count×minimum element wire size <= remaining input and reserve Vec capacity/copy bytes against a shared aggregate budget before allocation. Count nullable arrays and nested common structures across the whole message. Fixed schema nesting has no recursive type cycle. Input slices should be bounded before parsing; preserve complete-input validation and fail without returning partial typed results.

Strings must validate their declared byte length against remaining bytes and limits before copying; strict UTF8 can be a documented local policy compared with the authentic Java parser. Integers/u16 ports/bools use checked reads; invalid canonical boolean bytes and malformed nullable markers need explicit compatibility decisions based on actual generated parser results, rather than an invented upstream rejection claim. Unknown tag payloads can advance a checked cursor without copying. Error paths own and drop all partial structures.

Encoding needs a validation/size pass under the same limits before writing: reject unsupported version, oversize strings/arrays/aggregate or arithmetic overflow without growing an output buffer. Then write an exactly bounded canonical body. A temporary body can provide transactional append semantics so errors do not leave a caller buffer half-mutated. Keep the size pass and writer in agreement through meaningful maximum-boundary cases, not implementation-mirroring tests.

## Qualification

After source review/root claim and build lease, pin official schema/class bytes from all three already cached releases and use actual generated Apache classes for independently serialized vectors and parsing Rust-produced bytes. Required cells: empty/nonempty describe, null/empty/populated heartbeat changes; complete topology with regex/copartition/changelog configs; all active/standby/warmup assignments; endpoint ports0/65535; extreme signed epochs/offsets/status and nullable strings; member IsClassic; response topology null/empty subtopologies; group auth/coordinator/member/topology errors; unknown tags. Distinguish parser acceptance from broker semantic acceptance. A codec fixture is not an executed Java Streams framework or Kafka Streams coordinator qualification.

Hostile tests: all truncated prefixes of representative bodies; u32 length overflow/six-byte varint; massive nested counts with insufficient remaining bytes; maximum string/element/tag/aggregate limits and one-over cases; duplicate/descending/truncated tags; unexpected null in nonnullable arrays/strings; invalid UTF8; one trailing byte; unsupported versions. Retain observed Apache leniency separately where bounded Rust rejects. Test null vs empty values and every field across independent fixtures so a symmetric Rust codec omission cannot pass.

Run only focused default/MSRV codec and strict fmt/clippy gates initially, then root's exact-source immutable broader gates after registration. Do not spend a Cargo lease while the Admin owner is using it. Subsequent public Admin and real Streams-client wrappers require separate actual runtime routing/retry/semantic tests before CLIENT_SPOKEN or conformance status changes.
