# Share case dispositions

The retained Apache Kafka 4.3.1 sources are pinned to commit `26b251a451ce941d3d7a55e6487bcb7f16b5ad48`; their SHA256 hashes and exact URLs are in `upstream/manifest.json`. This comparison does not claim to execute the Apache Java test suite. Final Rust qualification and live evidence are separate gates.

| Rust socket case | Pinned Apache source comparison | Disposition |
| --- | --- | --- |
| Acquired subset in an independently generated four-record Java batch | `ShareCompletedFetchTest.testAcquiredRecords`, `testMixedRecordsAndGaps`, `testAcquireOddRecords` | Only offsets covered by AcquiredRecords are delivered, with the broker's delivery count. |
| Local poll limit and retained delivery | `ShareCompletedFetchTest.testSoftMaxPollRecordLimit` | Apache's batch-optimized limit is soft. Rust applies its configured local poll cap and buffers the acquired remainder; v2 RecordLimit separately constrains broker acquisition. The unset legacy per-broker request cap remains16. |
| Partial acknowledgement: successful neighbour and terminal InvalidRecordState | `ShareConsumeRequestManagerTest.testAcknowledgementCommitCallbackMultiplePartitionCommitAsync`; `ShareConsumeRequestManager.handlePartitionError` | Every requested partition outcome is checked. Success removes only acknowledged offsets; failure remains visible and does not discard the successful neighbour or unrelated acquisitions. |
| Retriable acknowledgement partition | `ShareConsumeRequestManagerTest.testRetryAcknowledgements` | RequestTimedOut retries only the incomplete partition within the original operation deadline. Successful partitions are never replayed. |
| Leader change during acknowledgement | `testFatalErrorsAcknowledgementResponse`, `testRetryAcknowledgementsWithLeaderChange`; `handlePartitionError` | NOT_LEADER_OR_FOLLOWER/FENCED_LEADER_EPOCH/UNKNOWN_TOPIC/PARTITION/ID are terminal for old acquisitions. Metadata is invalidated and the next fetch can reacquire on the new leader with a higher count. |
| ShareFetch and ShareAcknowledge session errors122/123; Fetch session-limit133 | `ShareSessionHandlerTest.testShareSession`; `testPiggybackAcknowledgementsOnInitialShareSession_ShareSessionNotFound` | Epoch resets to INITIAL. Old local acquisitions/buffers are invalidated. Fetch recovery is bounded; old Accept is not silently replayed in a new session. |
| Top-level response errors | `ShareSessionHandler.handleResponse(ShareFetchResponse)` and `handleResponse(ShareAcknowledgeResponse)` | Every non-reset top-level outcome consumes its session epoch. Retriable Ack errors advance before retry; Fetch errors preserve unrelated prior acquisitions. Fetch session-limit133 resets to INITIAL. |
| Cancelled roundtrip with delayed response | Rust `BrokerConn::roundtrip_deadline` cancellation guard and socket history | Cancellation poisons the connection. A new share session discards ambiguous acquisition metadata; delayed old Fetch/Ack replies cannot satisfy later requests. No network-layer change was required. |
| Renew | `ShareConsumeRequestManagerTest.testShareFetchWithRenewAcknowledgement`; generated 4.3.1 v2 schema/oracle bytes | Explicit Renew requires the target's Ackv2. The renewed offsets alone receive a new advisory deadline; delivery count and terminal acknowledgement metrics remain unchanged. |
| Lock expiry/release/reject/group isolation | `GroupConfig` and `modern/share/ShareGroupConfig` lock settings; actual current Docker runtime gate | Deterministic peer clock tests distinguish held, expired, released and terminal offsets. Group state and delivery counts are isolated. Current Docker must independently prove real expiry and reacquisition. |
| Coordinator movement and leave/resubscribe | Existing socket heartbeat/coordinator routing tests plus exact record/ack histories | Membership moves to the coordinator while share sessions remain on partition leaders. Leave closes sessions, clears owned buffers and allows reacquisition; resubscribe restarts heartbeats. |

The retained/decoded byte allowance also covers outstanding acquisition metadata across successive polls. Record counts and response arrays are checked before their corresponding allocations, and acquired ranges are validated before delivery. These are logical retained-storage limits; they do not claim a process RSS or codec-scratch bound. The externally held record/buffer codecs are unchanged.
