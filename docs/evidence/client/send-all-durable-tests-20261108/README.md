# send_all public regression controls

These public tests cover the producer route candidate and keep the 8,192-record fallback boundary inexpensive to run in CI. They do not prove that the shortcut was selected or detect a performance regression. Separate [instrumented controls](https://github.com/mingley/partitionline/actions/runs/42472219751) observe the route decisions; they use test-only counters and gates.

The clean test-only commit is [`281813872bb8c413d81b89760e8ab18ebb3aaf87`](https://github.com/mingley/partitionline/commit/281813872bb8c413d81b89760e8ab18ebb3aaf87), directly based on corrected candidate [`1af801af08e89931f53b811da49be896783e1ec4`](https://github.com/mingley/partitionline/commit/1af801af08e89931f53b811da49be896783e1ec4). The qualifying workflow was kept on a separate branch; it is not part of the test-only commit.

The tests send 31, 32 and 8,191 records to one warmed explicit route, checking input-order receipts, offsets, all mock-log values and buffered-byte accounting. They also exercise mixed explicit partitions, an interceptor that rewrites the partition, and sticky implicit partitioning. Each producer is explicitly closed after its assertions.

For 8,192 records, a manually polled public send uses a current-thread runtime and disables Tokio's cooperative budget. The first poll reaches the existing collection yield; the second reaches the existing full nudge-scan yield. The test checks that queue, acknowledgement, error, byte and mock-log snapshots have not changed, then drops the future instead of draining the full fallback. This is an implementation-sensitive boundary check; unchanged snapshots do not prove that no transient reservation occurred.
