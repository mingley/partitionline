# Client candidate source inventory repair

The first x86 CI attempt using v3 stopped before Rust compilation. Its source manifest required five ignored, untracked CPython cache files from the local workspace. They were absent from a fresh Git checkout.

V4 removes exactly those five paths from the base, baseline and fixed manifests. `preparation.json` lists every removed path and original hash. All remaining base paths are tracked in Git and match the checkout. Every retained source hash, all 19 changed Rust paths, the 122 required control identities, and every compressed and original patch byte are unchanged from v3. No required source or test was removed.

The runner now excludes only `.pyc` and `.pyo` files directly inside `__pycache__` directories when it inventories isolated source. The new cross-host control verifies that changing or omitting generated bytecode has no effect while real source and other fixtures remain recorded. All 18 lightweight client guard controls pass. These are Python and small process controls; they do not qualify Rust client behavior.

The candidate still combines streamed Admin decoding, cooperative aggregation, socket lifecycle fixes, JoinGroup retry deadlines, producer drain cancellation ownership, and small retry-chunk scheduling. CI selects 13 baseline cases before three final fixes, followed by formatting, strict all-target/all-feature Clippy, and full runs of ten chosen binaries in both feature configurations. The 108 library and 14 integration identities remain required. Six recently observed cooperativity failures have no claimed product fix in this candidate and remain gates.

See v3 for the original source preparation and reconstruction proof. Its source scope is sparse and excludes `docs/` and CI-only workflow/driver additions. The ordinary runtime stack remains 8MiB, with an explicit standard 2MiB group child control. The disk reserve remains 1.5GiB and builds use one Cargo job. Passing this preparation does not establish production readiness, live Kafka compatibility, multi-node durability, a release, or a performance ranking.
