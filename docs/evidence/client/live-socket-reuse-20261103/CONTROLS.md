# Proposed deterministic socket-transfer controls


These are specifications for new controls; **none exists or has run in this bundle**. Keep all current v16 test identities, assertions and timing unchanged. The gates below are explicit events, never sleep-based claims about scheduler progress. The actual implementation's owner and test hooks may differ, but witnesses must observe the real path rather than a hand-built surrogate state.

1. **Partial actual Worker write.** Add a test-only gate around the real plaintext `TcpStream` variant, not the existing `ScriptIo` fake. Finish Kafka startup first. Arm the gate for a subsequent Produce frame. Allow real `poll_write` calls to accept a total of exactly `K` bytes with `0 < K < frame length`, limiting each slice to the remaining allowance; account for short writes and publish the phase event only when the real stream has cumulatively returned `Ready(Ok(n))` for all `K` bytes. Hold further writes until released; the peer reads and confirms exactly that prefix while keeping the socket open and sends no response. Record the local physical socket identity and its owner slot generation before the gate, bound to the actual transport and peer trace; an address, correlation or role name alone is not an identity. Drive the actual `Worker::fire` path with a real accepted record. Add read-only, test-only snapshots at the same ownership boundary: `preparing.write_started=true`, connection counter 0, Worker in-flight queue empty, and no response received. Because `fire` mutably borrows the Worker, collect snapshots inside its poll path or through explicit shared instrumentation; do not obtain an illegal concurrent reference or manually set fields. The gate must register and wake the task correctly and preserve real byte ordering.
2. **Actual ownership decision.** While that write is gated, submit a different-role lease to the proposed owner specifically targeting the captured physical socket and generation. A test-only selector or owner decision event must prove this is the socket being evaluated; a request silently routed elsewhere does not exercise handoff. Witness its admission/decision point with an event: either an explicit busy decision, or a registered queued request whose serialization barrier forbids granting it while the Worker owns the stream. Check that no lease for that socket is returned before releasing the gate, and use an idle-socket positive control that reaches the same decision point and succeeds. The owner may instead satisfy unrelated work with a separately negotiated session in a different slot: if it does, witness that its physical identity and generation differ and that the original slot remains owned; this is not a successful same-socket handoff. If the implementation cannot service a busy decision while writing, a queued-state witness and subsequent release/decision ordering are required; merely observing `Pending` or sleeping is insufficient. Cancel or leave the initiating caller unpolled and keep a Producer clone: the independently running owner must still deny transfer and preserve the descriptor.
3. **Fully sent, unanswered Produce.** In a separate actual Worker run, let the peer read a complete valid frame and correlation but gate its response. Add a test-only event and gate immediately after the real `Worker.in_flight.push_back` and before the next `wait_one` can pop it. Snapshot the queue containing that correlation while the connection counter is 0 and no response is buffered. Use a fresh connection and an initially empty Worker in-flight queue; the event must reflect production code execution rather than manually setting fields. Observe the same lease denial/queueing. Release a matching response and verify full decode, acknowledgement and subsequent use of the *same actual socket*, with preserved per-socket negotiated API version and correlation sequence. Also test wrong correlation, malformed/incomplete response and EOF: quarantine or retire; never hand out an unknown stream or silently replay an ambiguous transaction. Exercise `acks=0` separately.
4. **Cancellation and physical retirement.** While the real write or read holds the stream, cancel/park the caller and request close or eviction, including pending flush and a live producer clone. Use a retained supervisor-owned cleanup path. On Linux capture the socket inode while still owned and fail closed on `/proc/self/fd` read errors (ignore only a disappearing entry's `NotFound`). Gate *before* a replacement dial and prove the inode is absent, transport users quiesced, and watcher/task joined at that point; checking only after `accept`, peer EOF, or handler-close event cannot prove no overlap. Add portable structural owner/drop accounting, TLS variants and deadline-expiry controls; after timeout, verify the slot is not reused until asynchronous cleanup really finishes.
5. **Provisional handshakes.** Independently gate and cancel at TCP connect, TLS handshake, ApiVersions, SASL and FindCoordinator in multi-bootstrap and rediscovery races, including losing tasks and a busy stream. Track every actual session and its local descriptor through publication, transfer or retirement. A replacement at the same address must perform its own ApiVersions and SASL and choose compatible versions; no cached ranges or credentials can be imposed on it.
6. **Session and ordering.** Use a controllable clock and real protocol peer to move the exact socket session across expiry at three explicit phases: (a) after preparation and immediately before its first actual Produce byte; (b) while the real partial frame in control 1 is gated; and (c) while the complete request in control 3 is awaiting its response. In (a), witness no application byte being sent after expiry; reauthenticate the same quiescent session or retire it and independently negotiate/authenticate another. In (b) and (c), no reauth or unrelated frame may interleave and no expiry-triggered transfer or automatic replay may occur. Either finish the original operation if permitted and fully quiesce before reauth, or retire/quarantine and report its ambiguous outcome. Exercise both session policy choices where implemented, including deadlines and caller cancellation. Use event barriers and continue polling after gate release so a late write or reauth cannot hide behind an initial `Pending`; wall-clock sleep is not the phase witness. Also test correlation-space separation, TLS identity and credential isolation, successful and failed reauth, exact public same-group retry ordering, unrelated-group progress under one saturated group, bounded count/bytes, and consistent timeout/cancellation outcomes. Test a small `Bytes` slice retaining a large backing allocation through queueing, retry, response and cancellation; keep the backing charge until the last library-owned reference is released, and separately document opaque user-owned buffers, allocator overhead and other exclusions. The control must test the claimed budget scope rather than infer a process-wide bound. Do not log secrets.
7. **Compatibility and qualification.** Run all original 15 mock tests unchanged plus all existing producer/connection tests in both default and all-features modes using stable Rust. Evaluate the 450 ms stale-metadata assertion separately from handshake counts. Then validate against real Kafka, TLS/SASL variants, fault and cancellation matrices, memory/control responsiveness, and an x86 benchmark against named comparable implementations under published configurations. Do not infer a speedup from fewer handshakes; do not claim production readiness or fastest performance without those results.
