# Negotiated producer socket reuse: source-only design

Status: **design and diagnostic controls only; no Rust patch, native build, test, or performance result**. V2 preserves the separately frozen v1 and adds explicit same-socket/generation control and session-expiry phase requirements from independent review. The exact v16 fixed input catalog and source pins are in `source-pins.json`. `extract_projection.py` preserves the hosted job's two visible failure projections, without asserting that the unavailable full report artifact was independently verified. `model.py` exercises a small source-derived state illustration, not the implementation. No existing test or threshold was changed.

## Observed scope

The hosted v16 job log reports 32 passed and 15 failed mock-produce tests in each feature profile. Its output labels the test-result projections “unverified; full receipt retained”; the projection is not a socket trace. The failures include handshake-count assertions at producer startup and after coordinator moves, and latency assertions. Counts such as 2 rather than 1 do not alone identify which physical socket carried each request. The earlier *v10* native wire audit, separately pinned in `source-pins.json`, did observe actual node/socket IDs for `send_all_redials_leaders_while_refreshing_metadata`: parallel first leader handshakes and metadata handshake, a second leader pair after metadata returned, and Produce on that second pair. Those facts belong to that v10 run, not a v16 trace or a performance benchmark. Same failure identities on main predate v10 under the recorded matched test settings; identities do not prove identical causes.

The original `send_all` test sets a 40 ms connection idle limit, waits 60 ms, configures 250 ms ApiVersions and 250 ms Metadata delays, and asserts less than 450 ms. V10's fresh metadata socket performed these two operations sequentially, so its Metadata response alone arrived after roughly 504 ms. Reuse helps only when an eligible live socket is available; it is not a demonstrated solution to this exact threshold. Sending on stale metadata would alter the documented `send` freshness contract and requires a separate API and correctness decision. Retaining an idle-expired connection or sending a request on a fresh unnegotiated session cannot be assumed safe.

The single-broker startup test requires one ApiVersions at the end of initialization; the idle-coordinator test later expects at least two simultaneously open metadata/coordinator connections. The current implementation uses independently negotiated role sockets, conflicting with the former count. A differently designed owner might share a session at startup and later establish another connection, so the fixtures are not proven mutually impossible for every architecture. Phase-specific controls and unchanged tests must decide any concrete design.

## Why the connection itself must move

In pinned `src/producer.rs`, `Producer::open_bootstrap` (around 2001–2069) gathers completed handshakes, retains one `BrokerConn`, and marks completed sibling connections closed and invokes `release_if_closed` after saving their ranges. This does not by itself prove that their local descriptors have been destroyed. `open_conn_with_known_versions` (4453) correctly negotiates every new socket. `open_produce_socket` (4464) likewise opens a new session. `group_coord_roundtrip` (5686) discovers into a local connection for each call; its retry can start a replacement before retiring the prior connection. These are separate paths, so a single group cache would not establish that all 15 tests pass.

An eligible entry must own the **actual** `BrokerConn` plus its TLS session and peer identity, authenticated principal and session lifetime, all negotiated API versions, correlation state, buffers, pending frame state, idle watcher and transport. Never copy negotiated ranges or authentication onto a new socket; a broker can change at the same address. Keep reuse within the same producer security/configuration domain, and validate the target broker/address and generation against the authoritative metadata or coordinator response. Select and encode the operation's API version using the actual target session. In particular, review bootstrap-derived transaction version choices and any body encoded before coordinator selection.

The v16 raw Produce path obtains a correlation and calls `write_all_timeout` directly (`producer.rs:8509,8603–8638`); it does not call `BrokerConn::send_deadline`, the method that checks SASL expiry and increments the connection's counter (`net.rs:2201–2217`). The raw Produce path in this pinned file has no `is_session_expired` or `needs_reauth` call. This is a source-inspection qualification gap, not a demonstration that an expired session was used or accepted. A candidate must check expiry at the actual first-write boundary. If a session expires during a partial frame or while an application response is outstanding, retain and resolve that original operation where the protocol permits or retire/quarantine it and report an ambiguous outcome; never silently hand off or replay it. Reauthenticate only after complete wire quiescence, or retire and establish a new authenticated session. Do not expose credentials or interleave authentication and application frames.

## Exclusive ownership and atomic eligibility

The safety invariant is one durable transport owner per physical socket. A `BrokerConn` is published to a supervisor before any cancellable negotiation/authentication/discovery await, and the supervisor owns every concurrently opened or provisional socket until its child task and transport have either transferred to a live slot or physically retired. Cancellation of a caller, a dropped future, a timeout, or a losing bootstrap race never makes a local future the final untracked owner. A connection may be used by multiple roles through a single scheduler or transferred exclusively between owners; concurrent writers/readers must be serialized by that same owner. This proposal does not prescribe `BrokerPipeline`: it owns a connection, but its current command admission awaits `cmd_tx.send` without applying its request deadline there; its last-handle Drop aborts rather than joins its task, and its retained payloads and descriptor retirement need independent audit. It is not a ready-made proof.

A transfer is only proposed while a single atomic ownership protocol has prevented new writes, receives, reauthentication and retirement from racing the decision. The old owner must have relinquished the connection and all its transport handles. Conditions to establish first include no partially written request, no outstanding expected response or active response decode, no hidden `Worker` preparation/completion/split/ack/response state that still claims the connection, no queued unsolicited or mismatched frame, no pending reauthentication, no closed/expired session and no expired idle policy. This list is necessary, not an implementation or proof. Empty userspace buffers cannot establish that the peer will never send more bytes or close; future I/O still validates correlations, frame bounds and failures. Ownership transfer and close must be linearized with registration and generation changes, with no await between a committed transition and recording its durable owner.

`BrokerConn::in_flight()` alone is inadequate. `Worker::fire` marks `preparing.write_started` before awaiting the raw write. During a real partial write its connection counter and `Worker.in_flight` can both be zero; after a successful full Produce write, the Worker queues its own `InFlight` without incrementing the connection counter. `Preparing::take_groups()` does not reset `write_started`; `Preparing::begin()` resets it for the next batch (`src/producer/prepare.rs`). This is a conservative write-history marker, not by itself an exact current-write phase. An `acks=0` write has no broker acknowledgement, but it still must finish its write and local completion before any handoff. `has_queued_response()` only examines its local read buffer and watcher prefetch; it does not establish that the kernel, peer, or another stage has no unresolved response. `model.py` illustrates these states; it does not execute a Rust Worker or demonstrate any actual race.

Each owner should keep one absolute operation deadline from admission through connect, TLS, ApiVersions, SASL, queueing, request/response and any requested cleanup. Accepted work must have count **and byte** budgets before copying large group IDs or encoding bodies. Define the byte budget over retained library-owned backing allocations and their full lifetime, not just visible slice lengths: a tiny `Bytes` view can keep a large allocation alive. Attribute shared backing only once, keep its charge until the last library-owned reference is gone, and include queued/retry/response buffers and provisional/cleanup ownership in the stated scope. If external or opaque backing cannot be sized reliably, reserve a conservative bound or copy under budget and state exclusions; do not present the result as a process-wide memory bound. A per-group ordering requirement must define the public-call registration point and hold through every retry, including metadata/encoding work. Do not allocate all physical-lane permits to waiters for one stalled group; bounded per-group admission and cross-group scheduling must have explicit fairness and timeout policies. These are design requirements, not established properties of the previous draft. A completed write with an unknown response is an ambiguous operation: do not automatically replay a non-idempotent request. Existing idempotence, transactional, retry, and epoch semantics need independent compatibility checks.

## Retirement and close

`BrokerConn::close()` sets a flag. In the pinned `net.rs`, `release_if_closed()` can shut down a TCP write half while leaving `ConnIo::Tcp` and its descriptor alive, and `BrokerConn::drop` only aborts the idle watcher. Neither a peer EOF nor a fixed number of yields proves local descriptor destruction. The supervisor must retain the slot until stream users and watcher tasks are quiescent and the actual local transport is dropped; retirement must not depend on an unpolled caller continuing. A new slot generation may not reuse that slot until retirement is witnessed. Independent healthy sessions to one broker may coexist; this is not a global one-socket rule.

After close has first been polled and registered, the proposed contract must stop admission and request supervisor shutdown even if flush is pending or the close future is dropped; clones and parked operation futures must not prevent an owned cleanup task from progressing. Merely constructing and dropping an unpolled future cannot start close. Preserve the original close deadline: if full retirement cannot be witnessed by then, report timeout rather than success and keep bounded deferred cleanup ownership. Verify behavior when the runtime itself is shutting down; do not promise async cleanup after its executor has stopped. TLS `close_notify`, TCP half-close, abort, fd destruction, peer scheduling and buffered writes are distinct observations.

## Required controls

The separately documented [control designs](CONTROLS.md) require actual Worker partial-write and fully-written/unanswered response phases, a decision targeting the same physical socket and slot generation, cancellation while a caller is parked, local descriptor retirement before replacement, session-expiry phase and authentication checks, bounded scheduling, and unchanged original tests. None exists or has run in this bundle.

## Prior design and review

The earlier group-supervisor draft and independent review are pinned in `source-pins.json`; they are not adopted here. Its reviewers found that same-group waiters could consume all eight lanes and block other groups, retry ordering did not encompass a whole public call, encoded request bytes preceded admission, and close cancellation during flush remained unresolved. Existing group socket cache and lifecycle draft controls had physical-retirement and phase-witness limitations. This design sets out what a future implementation must prove; it does not cure those findings or qualify the rejected draft.
