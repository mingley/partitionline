The selected contract is the Kafka 4.3 uniform, nonadaptive state machine with Rust conservative packed-byte accounting. Only a successful initial enqueue charges a record; new cohorts add 61 bytes. Keyed and explicit records participate in the real tail, but do not charge the unkeyed counter. Random draws may repeat a partition. Topic, outstanding cohort, and retained topic-text ceilings are 1024, 4096, and 256 KiB, including caller requests above those ceilings. Pressure admissions use stateless singleton cohorts. Mutable policy state is fresh for each Producer, even when configs share their partitioner Arc.

Initial admission takes metadata then policy locks, computes a pure route and prospective append, performs the real nonblocking channel send, and commits only on success while those locks remain held. The opt-in branch bypasses the old fast/fallback double-selection path. The asynchronous path waits outside these locks under the original absolute max_block deadline; a BufferReservation releases payload capacity if the future is dropped before enqueue. Accepted Pending records retain ownership after caller cancellation, matching the existing ambiguous-delivery contract. Delivery deadlines and queue timestamps begin at actual admission.

Each tracked cohort retains only bounded metadata and a unique worker token, not payloads. Tags carry cohort identity, original append ordinal, and captured topic UUID. The worker pulls all committed channel records under the policy lock and seals exactly one complete cohort at an actual drain. Different cohorts and pressure singletons cannot be merged merely because they share a partition. Batch byte and record limits are enforced when cohorts open or append; a valid record above the batch target travels alone. Partial drain below the sticky byte threshold preserves the sticky counter; an actual sealed/empty tail can complete a deferred switch with zero added bytes.

Outstanding membership persists through encoding, transaction admission, writes, in-flight responses, and retry transfers. Retriable failures seal the cohort and transfer its existing tags without an accounting call. Metadata movement between transfers rebinds ownership only after a real retry enqueue; displaced workers transfer their remaining members, avoiding a half-cohort wait on two workers. Original append ordinals restore order before encoding. Idempotent sequence assignment remains in the existing encoder path. If a terminal failure removes an already sequenced member, cancellation propagates to the remaining cohort rather than resending a shortened sequence history; the row remains until every surviving owner has completed or failed.

Terminal completion is centralized: acknowledged responses, local acks=0 completion, fail_pendings/fail_groups, retry guard cancellation, pre-send transaction/encoding/write failure, expiry, worker drop, and shutdown all retire the same outstanding membership. Worker and retry actor guards preserve payload ownership. Close and last-handle drop clear policy history after publishing Closed and stopping actors. Late drain/retire/rebind callbacks never insert state. Old topic-lifetime callbacks cannot rotate a new topic lifetime. Produce v13 uses the admitted UUID for opt-in queued/retried records; metadata refresh affects future admissions. Older Produce versions retain their existing topic-name limitation.

The default and existing custom partitioner branches remain on their previous routing and packing paths. The new inline tag changes the private Pending layout, and opt-in packing sends one complete cohort per request. Throughput, CPU, latency, allocation, and memory effects have not been measured; no performance benefit is claimed. The fixed-seed Rust RNG is for reproducibility and is not Java RNG identity. The SDK caller is prepared against pinned source but has not executed. No exact Java accumulator/compression metric or whole producer history equivalence is claimed. Native librdkafka's time-based sticky policy remains a separate benchmark contract.

Prepared gates are stable/MSRV strict Clippy with the actual root clippy.toml; the new policy and framed socket tests; existing default/custom routing, buffer ownership, cancellation, idempotent/transactional recovery and mock Produce regressions; full four-cell default/all-feature client QA on the actual pushed source; genuine Java reference execution and immutable output capture; and matched keyed/unkeyed measurement cells with explicit policy, packed-byte accounting, eligible leaders, seed availability, request counts, byte counts, CPU/RSS and latency. All Cargo, JVM, live-broker and performance gates remain unexecuted in this source stage.

The post-review correction replaces 31-bit modulo selection with deterministic rejection sampling. The pure choice returns its post-draw RNG state after every attempted draw, including rejected values. A route/append plan installs that state only after successful channel enqueue; failed routing, buffer/slot/channel admission, or cancellation cannot consume RNG or charge policy state. A cached partition with no selection draw does not consume a draw in pressure mode. Three additional policy cases exercise rejection for non-power-of-two counts, returned-state rotation/pressure behavior, and cached pressure without a selection draw. These cases are prepared, not executed.

The producer-wide opt-in record budget is separate from payload byte accounting and channel row capacity. Its default and hard ceiling are 100,000, clamped to 1..=100,000. The count includes reserved admission slots plus accepted records: an asynchronous future blocked on byte/channel capacity may retain a reserved slot before enqueue. A private non-Clone RAII permit is acquired once and owned by each Pending through worker queues, in-flight requests, retry actors, and terminal drop. Failed admission and pre-enqueue cancellation release it; accepted caller cancellation preserves it until delivery/error ownership terminates. Retries neither acquire another slot nor recharge packed bytes. Null/empty payloads and buffer_memory=0 remain bounded by this record capacity. Existing QueueFull and absolute max_block Timeout behavior apply when capacity is exhausted. Close wakes waiters without synthetically clearing slots still legitimately owned by paused futures.

The caller input vector staged by send_all is outside this admitted/reserved-record bound, as are other existing producer/network buffers. This is not a whole-process RSS bound. Six additional framed socket cases prepare cap-two null/empty pressure, reserved-slot cancellation while byte-blocked, cancellation while capacity-blocked, accepted caller cancellation, retained retry slots and terminal release, and encoding/routing failure release. No new performance result or passed runtime case is claimed.
