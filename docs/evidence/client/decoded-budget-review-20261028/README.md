# Decoded allocation budget review

This is a static proposal, not an implemented fix or measurement. `inventory.json` pins the base commit and an uncommitted working-tree snapshot by SHA-256. Client edits were still in progress; this is not a final candidate or proof of a completed test run. Its 890 lexical matches include encoders, tests and sites with existing validation; they are not a vulnerability count.

Priority paths:

1. Before authentication and normal use, `decode_api_versions_response` in `src/protocol/api.rs` reads `get_array_len` and allocates that many `ApiVersion` entries. The length helper in `buf.rs` checks only `count <= bytes remaining`, although each API version needs at least six wire bytes. The normal socket frame cap is 100 MiB (`src/net.rs`).
2. Fetch v4–v18 (`src/protocol/fetch.rs`) preallocates topic/partition vectors and `SlotList`s immediately from peer counts. `EncodedBatch::reserve_hint` (`src/protocol/records.rs`) and `reserve_fetch_records` (`src/consumer.rs`) preallocate output records based on the peer batch count before records are validated. A bad uncompressed count of N with N section bytes passes the current check; compression can make the network input much smaller. A small fixture can allocate many times its wire size in object slots. Large `Vec` reservations can consume virtual address space without immediately increasing RSS on overcommit, so measure both allocated bytes and peak address space; do not assert physical OOM without an actual run.
3. `assemble_open_batch` and `decode_record_mode` in `src/protocol/records.rs` reserve the full untrusted record and header count after checking only against remaining bytes. This affects both the public wire and strict internal decoder paths.
4. `src/protocol/txn.rs`, `group.rs`, `share.rs`, `acl.rs`, and many `admin.rs` decoders follow similar patterns. Some specific paths such as WriteTxnMarkers have schema-specific minimum checks. The ShareFetch decoder already charges its topic and partition objects to a decoded-byte allowance, though endpoint and nested record/header allocations require separate review. Audit each path rather than treating every lexical match as exploitable.

A shared design should pass one mutable `DecodeBudget` through the outer response and all nested decoders, including compressed batches and flexible tags. Budget separately and cumulatively: frame bytes, decompressed bytes, array elements, owned container capacity, strings/headers, and CPU work. Charge checked `count * size_of::<T>()` before large allocation; distinguish shared `Bytes` slices from their retained backing frame and keep charges alive until the owner releases that backing. Avoid silently releasing a reservation when a returned object or offloaded task still retains memory. Use fallible growth and bound *each* expansion, including `String`, nested vectors, hash tables and decompression output; `try_reserve` alone does not establish a byte budget. Limit initial reservation and grow with validated elements. Check version-specific minimum remaining wire size with checked arithmetic before planning, preserving nullable/compact semantics and all legitimate tagged fields.

Existing public decoders can keep their signatures via explicit safe defaults and gain additive `*_with_limits` APIs; consumer/admin/producer connection paths should pass configured budgets through, aggregate nested allocations and across concurrent responses, and account for broker exception rules for a single oversized batch. Do not infer that `max_poll_records` or byte-only `buffer_memory` caps object slots unless the actual owner accounts for them. Avoid imposing a small undocumented count cap that silently breaks supported large responses. Reuse `Vec` and `BytesMut` capacity with `reserve(required_total - len)` only when capacity is short; `reserve(required_total - capacity)` is incorrect when len is lower than capacity. Concrete examples in this snapshot include `reserve_fetch_slots` in `src/protocol/fetch.rs`, `reserve_additional` in `src/protocol/api.rs`, and `reserve_len` in `src/producer.rs`. Request builders in `src/protocol/admin.rs`, `api.rs`, `fetch.rs`, and `share.rs` contain the same pattern for `BytesMut`. `CompressScratch::reserve_section` and header-wire reuse in `src/protocol/records.rs` also need review. These examples do not themselves prove corruption; they can cause later geometric reallocations and bypass an intended fallible reservation. Measure and test with `len < capacity < needed`, not only fresh or full buffers.

Tests should include: (a) a v4 response declaring N topics with only N bytes remaining; (b) one small v4 topic with N declared partitions and N bytes remaining; (c) corresponding flexible v12 and v13+ topic-ID versions; (d) a CRC-valid uncompressed batch declaring N records with N bytes but invalid first record; (e) a record body declaring N headers with N bytes remaining; (f) a small gzip/Snappy frame expanding within the existing byte ceiling with a huge declared count; (g) an actual fake broker feeding that batch through consumer Fetch, asserting protocol error, no position advance, bounded admission and no retry storm. Run malformed input in subprocesses under explicit address-space/resource limits or a scoped counting allocator; check actual allocated/capacity and peak address space, not just return codes. Include valid many-record inputs, nullable/empty arrays, duplicate/unknown tags, fragmented Buf, repeated decode reuse, and pooled response/cancellation lifecycles. Compare throughput/allocation counts on pinned realistic workloads after correctness and bound checks pass.

`encode_record_batch_cooperative` also yields after appending to the caller's buffer and can leave a partial frame if dropped. An RAII rollback guard can truncate to the entry length on cancellation; add a forced-yield cancellation test for both normal and wrapped paths, with a preexisting prefix. Any scratch-buffer alternative must measure its extra copy/peak memory and retain cancellation correctness.

This work does not establish production readiness, peer compatibility or fastest performance.
