# Group coordinator ownership design to validate

This is a design proposal, not an implemented or benchmarked change. The old group-cache patch remains rejected until every path below is implemented and independently verified. A partial switch from `release_if_closed` to a physical-retirement helper is insufficient: the old discovery, retry and fallback paths create other connections in local futures, and a caller that stops polling can keep a cache guard indefinitely.

A practical direction is a bounded set of supervised group-operation lanes. Each lane has a durable, independently owned state containing its cached connection and a bounded array of provisional connection slots. Every physical socket is placed into one of those slots immediately after connect returns, before ApiVersions, SASL, FindCoordinator, decoding, or another await. Before reuse of a slot, terminal cleanup must replace its `ConnIo` with `Closed` while holding the stream lock. The shared state keeps that closed or unretired owner on timeout or cancellation; a later attempt may not dial a replacement in the same slot until physical retirement has completed. Newly opened sockets negotiate and authenticate for themselves. TLS/connect cancellation before a `BrokerConn` exists also requires a separate proof that the connector future owns and drops its raw socket; this must be tested rather than assumed.

The lane worker, rather than a user-owned future, performs the I/O. The user's receiver can be cancelled; the worker observes that cancellation before dispatch and at I/O await points, marks the connection uncertain before a request can be written, drops the borrowing I/O future, and retires the slot. A request whose outcome is unknown is not automatically replayed merely because the connection closed. After a completely decoded, non-coordinator-error response the worker may retain the same socket for the exact group. Closed, idle, expired and reauthentication-due sessions must be rejected before reuse. A response decode error or cancellation while decoding leaves the socket uncertain.

The supervisor must atomically register each worker against shutdown. For example, under one short non-async manager lock, check the durable closed state, register a worker handle, and only then release a start gate. Close sets the closed state under that same lock and aborts/joins registered workers; a concurrent registration cannot slip past the shutdown snapshot. Queueing and lane count must have explicit bounds and use the original absolute request deadline. Same-group ordering, concurrent groups, capacity exhaustion, cancellation of queued work, and potential head-of-line blocking are design tradeoffs requiring tests and measurement. A silent fallback to the old unowned per-call discovery path is not acceptable.

To preserve multi-bootstrap resilience, concurrently opening more than one bootstrap needs one persistent provisional slot per attempt and a bounded race. Losing tasks must be stopped or joined, and their slots physically retired, before those slots are reused. FindCoordinator retry may overlap a speculative previous-coordinator dial, but both attempts and any resolved target must have distinct retained slots. If a deadline prevents retirement, retain the slots, return Timeout, and arrange bounded cleanup; do not return success or redial through an unretired slot. This design must preserve terminal coordinator errors, request budgets, broker-advertised versions, SASL session isolation, and Kafka's transaction error classification.

Close must stop new admission, cancel or abort active workers independently of whether their callers are being polled, and wait for worker termination and physical retirement within the original deadline. If any owner cannot be retired in time, close returns Timeout while an explicit bounded cleanup owner retains it. Cancellation of the close operation itself needs the same registration/cleanup handshake. Runtime teardown and multiple concurrent close calls must not discard an outstanding owner or permit post-close publication. A remote EOF or `BrokerConn` closed flag alone is not proof of fd destruction or of the broker's outcome for an earlier request.

Required tests include a parked caller, retained clone, held stream lock and cancellation during partial write; blocked ApiVersions, SASL, and FindCoordinator; multiple simultaneous bootstrap candidates; cancellation while lookup and speculative target are both live; a moved coordinator followed by a fresh physical negotiation; and shutdown racing worker registration. Linux socket-inode controls should assert local fd absence before reusing a slot. Equivalent TLS and non-Linux ownership tests, close-deadline tests, actual Kafka interop, and measurements of hot reuse and contended groups are still needed. The proposal changes scheduling and can regress latency or throughput; no speedup or production readiness is established.
