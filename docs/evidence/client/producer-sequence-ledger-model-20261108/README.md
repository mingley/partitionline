# Producer sequence ownership: isolated model

This is design evidence, not a producer fix. Both models below remain unapplied. The client still has the [seeded single-partition rollover failure](../producer-sequence-rollover-20261108/README.md) and the [forced worker-cancellation failure](../producer-sequence-public-20261108/README.md). A production implementation and its performance have not been qualified.

## Source review

Reviewed client commit [`b51f645d9e90a3158906c52bdeaafbf86dffcac0`](https://github.com/mingley/partitionline/commit/b51f645d9e90a3158906c52bdeaafbf86dffcac0). Its `src/producer.rs` blob is `1e7733c136e54b532cdc8bddabd1e0c828e50ed2` (SHA-256 `3d65fcceecbb43c1a974f7f6b7bd58c8a310930f6bcced9052a00e88700eb37f`). All following links use that source.

- [Sequence counters and per-record stamps](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L10381) use saturating arithmetic; [the counter](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L11217) can reuse `i32::MAX` instead of wrapping. The existing rollover witness is a seeded repository mock, not a real Kafka observation.
- [Assignment](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L10402) reserves before the asynchronous stamping walk completes. Cancellation at its yield needs an owner for the entire accepted batch and reservation. [Rollback](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L10453) compares a numeric base and count, with no nonreused reservation token or generation check. A write error can enter [rollback after `write_all_timeout`](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L8498); the amount delivered on an error requires separate proof.
- The worker [loads producer ID, epoch, and generation separately](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L8354) before awaiting sequence assignment. Identity transitions update the sequence map and identity fields separately in [EndTxn](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L1456), [local epoch bump](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L1482), [broker epoch bump](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L5492), and [identity renewal](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L5535). These source observations identify interleavings to control; they do not establish that a particular externally visible identity race occurred. The generation increment is not checked for exhaustion.
- Each [`Pending`](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L858) carries a numeric base and batch length but no unique batch identity. [Readiness](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L7659) counts leading records with the same numeric base, without matching topic, partition or generation. [Packing](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L10153) tracks a numeric base per partition and applies record and byte limits; [encoding](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L11005) takes the first record's sequence. A scenario with a partially requeued batch followed by a different partition with the same base could make the count misleading. The public client has **not** been shown to reach that schedule; neither a real-broker consequence nor a failure is claimed for it.
- Flush and close go through [`drain_inflight`](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L8106), which [calls `fire` directly](https://github.com/mingley/partitionline/blob/b51f645d9e90a3158906c52bdeaafbf86dffcac0/src/producer.rs#L9255) instead of passing through `can_fire`. Fixing only the readiness predicate cannot guarantee a complete original batch. Readiness, selection, retry and the encoded group need to agree on the same nonreused batch identity and completeness rule.

## Isolated models and controls

The first model, [`1ab0eca942184cec6c0f5f1ca2c43077a80d9923`](https://github.com/mingley/partitionline/commit/1ab0eca942184cec6c0f5f1ca2c43077a80d9923), passed eight tests in [run 42474893339](https://github.com/mingley/partitionline/actions/runs/42474893339), but is rejected. After an ambiguous write, it allowed a successful retry to clear the entry and permitted later writes or an identity change without proving the earlier attempt could no longer arrive. The passing tests did not establish that safety property.

The revised isolated model is [`4d4e5543a1105669f8c854c4a601ccace845ad74`](https://github.com/mingley/partitionline/commit/4d4e5543a1105669f8c854c4a601ccace845ad74); `tests/producer_sequence_ledger_model.rs` is blob `4d16e16c51e56bec1047d2456509dc394d7609a5`, SHA-256 `091ff0276da9b5672d7794a7f5dba763d917bcdf8d08a3739a5dc1bc01078838`. It models a bounded, one-partition FIFO of nonreused tickets containing an opaque partition key, generation, sequence base and count. It allows only the head to write, permits rollback only for the exact unwritten tail, uses modulo `2^31` arithmetic, and checks token and generation exhaustion. Its caller must guarantee unique partition keys and root accepted batch data across cancellation.

The model retains an uncertainty fence after an ambiguous attempt, even if an identical retry is acknowledged. There is no settlement operation: a later reservation, unrelated write and new identity remain blocked indefinitely. This deliberately loses liveness and is not a proposed production implementation. The model assumes external proof of quiescence for identity changes and does not model transaction fencing, stream semantics, data ownership, callback completion, cross-partition atomicity, socket cancellation, or topic-incarnation mapping.

[Run 42475038806](https://github.com/mingley/partitionline/actions/runs/42475038806) checked out qualification commit [`e149a99abd54725dc6aaf5910dc00318991039cf`](https://github.com/mingley/partitionline/commit/e149a99abd54725dc6aaf5910dc00318991039cf), compiled the model with `rustc --edition=2021 -D warnings --test`, and passed nine tests on an x86-64 Microsoft-hosted AMD EPYC 7763 runner with stable Rust 1.99.1 and LLVM 23.1.1. The tests cover arithmetic against a widened oracle, token ABA, two-thread reservation, FIFO, retry uncertainty, guarded rollback, identity quiescence, bounds and different opaque partition keys. Four intentionally broken mutants—numeric-only rollback, disabled FIFO, identity change without quiescence, and identity change with outstanding uncertainty—failed their corresponding tests as expected. These are unit controls of the model, not tests of the producer or an exhaustive proof. The workflow made formatting diagnostic only; `rustfmt --check` reported differences, so strict formatting did not pass.

No integrated hot-path cost was measured. These model results provide neither a throughput estimate nor a basis for performance or release claims. The next implementation needs a cancellation-safe owner for whole accepted batches, a bounded reservation journal with generation and write-attempt fencing, synchronized identity transitions, and a defensible way to resolve ambiguous attempts. Qualification must include public-client histories for wrap, concurrent batches, reordered retries, epoch changes and cancellation, plus actual producer performance and broker compatibility.
