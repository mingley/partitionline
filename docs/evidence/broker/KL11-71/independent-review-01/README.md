# Source-only SASL reauthentication review

Reviewed the exact six-file cb925db2 packet without modifying it or launching a compiler, server, socket test, SDK or external connection. All candidate and original-copy bytes/full 07777 modes were rechecked. This is an installation review, not KL11-71 qualification.

One concrete source-derived blocker is the expired-ready-operation delivery path in `partitionline-broker/src/transport.rs:807,846,870,873,886`: `timeout_at` accepts an inner Ready result before polling its elapsed timer. The pinned Tokio 1.53.1 source confirms that ordering at `src/time/timeout.rs:217`. A handler that crosses the finite SCRAM session deadline during one poll can return its reply; the next immediately-ready prefix/body writes can finish after expiry. `Session::response_written` detects the expired authority only after those bytes have been emitted. It correctly refuses identity activation and closes the socket, but cannot retract the reply.

The source-only proposed regression `expired-ready-handler.regression.rs` reuses the actual candidate SASL socket helpers. It keeps a 100ms renewable profile and makes an authenticated handler synchronously return after 300ms. This checks post-return authority fencing; it does not demand interruption of synchronous work. The expected no-reply assertion has not been run, and actual socket readiness remains a runtime condition to validate. A deterministic custom always-ready AsyncWrite test can supplement it when compilation is authorized.

Require an explicit absolute-clock/lease validation after handler completion and before beginning response writes, retaining the original request authority and pending-renewal deadline. Check validity at write poll boundaries too if the documented contract includes write futures that themselves cross the deadline and return Ready. This preserves the documented limitation that blocking code cannot be preempted; it discards the result once control returns. Retain the final post-write activation check. OAuth final renewal writes currently race the old lease and check both old and new leases afterward; add meaningful new-lease revocation during a blocked final write coverage before claiming full authority/write qualification.

Source review found no second demonstrated identity/mechanism or cancellation ownership defect. Exact mechanism, name and authority (including OAuth issuer) remain invariant; generations may rotate. Renewed identity is hidden while pending, the old lease survives through final writing, read/admission/auth/write deadlines retain the earlier authority, and lifetime-zero/raw/v0 behavior is scoped correctly. The operator option is bounded and opt-in. Connection Drop initiates draining; explicit shutdown remains necessary to observe all owned joins.

Coverage remains incomplete: all 17 new Rust/socket tests are uncompiled/unexecuted; no independent Java/native-C/public-Rust renewal proof, actual final-proof blocked-write coverage, or lease/task resource census was produced by this review. The reported 80 earlier literal codec controls were not rerun here. The docs' WORK qualification disclaimer is accurate.
