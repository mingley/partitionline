The independent storage-history checker reads retained real rolling-store publication checkpoints. It imports no Rust code or expected runtime result. Its own CRC32C implementation checks the Castagnoli known vector; it parses PLSEGM01 manifests, PLJRNL01/PLENTRY1 journals and PLSEEK01 checkpoints. All formats use bounded files, entries and descriptors. The static BASIC seed comes from the committed ordinary-record fixture; only its eight-byte base offset changes in these histories. The acknowledged floors are independently fixed at 1, 2, 1 and 4 for the four named fault schedules.

The checker verifies selected generations, contiguous offsets, complete entry/header/payload checksums, exact seeded Kafka batches, descriptor fingerprints, checkpoint physical positions and cumulative prefix timestamps. Paired interrupted/recovered states must retain the acknowledged prefix. Unselected staging files are hash-retained without becoming committed authority.

The negative driver copies a genuine selected state and alters six cases. Five preserve enclosing file CRCs while changing semantic positions, prefix maxima, fingerprints, seed value bytes or selected generation. The seed value is the valid one-byte `v` at batch byte 68, changed to `w`; Kafka and journal CRCs and descriptor fingerprints are then recomputed. The sixth deliberately truncates a selected payload and is classified as structural. Every case must fail at its intended check. These are checker counterexamples, not compiled Rust mutants. The initial development generator incorrectly assumed the value was two bytes from the end; both its partial original output and fresh authentic failure reproduction are retained.

This is a finite selected-file publication proof. It does not infer active torn-tail repair, configured checkpoint intervals, constructor resource bounds, power-loss safety, retention, compaction, replication or performance. Separate compiled tests and source review cover their stated contracts.

Final qualification runs the exact pushed checker and generator on all four immutable Rust test lanes and retains their input/output hashes. Source staging and development success alone do not close KL11-09.
