The API21 corpus uses the official Apache Kafka 4.1.2, 4.2.1 and 4.3.1 DeleteRecords serializers, request/response headers, parsers and `getErrorResponse` helpers. The generator has no partitionline dependency and does not inspect Rust output. The normal response policy is an independently declared ordinary single-node RF1 contract with exact seed floor/high watermark; it is not an executed Apache broker/controller result. Public serializer classes merely encode and parse that policy. Actual UnifiedLog outcomes and source-only facade behavior are retained separately in the parent oracle.

Each release has 121 cases: 115 response goldens and six explicit local structural rejections. API versions 0–2 are covered, with request header versions 1/1/2 and response header versions 0/0/1. Frames contain the full header and body without the four-byte length prefix, client ID `retention-oracle`, correlation ID 7. `cases.tsv` has five columns: name, API key, version, seed, expected outcome. Every named case starts with a fresh seed; no expected offset depends on a prior case.

The catalog has alpha UUID2/two partitions and __consumer_offsets UUID3/one partition. `fixture` contains the frozen 104-byte batch at offset0/count3 and 78-byte batch at offset3/count1 in alpha0 (high watermark4/floor0); alpha1 is empty. `fixture_floor_2` retains the same containing whole batch and records durable logical floor2. `fixture_empty` has catalog only. Success returns max(previous floor, requested offset); -1 means confirmed high watermark. Other negative or above-HW offsets return error1 and low watermark-1. Unknown names/partitions return error3; the known internal topic returns error17. The independently declared normal map uses the final duplicate offset, sorted topic/partition results and omits topic rows with no partitions. This deterministic order is local policy; source KafkaApis does not promise its map iteration order. Timeout scalars are parsed and accepted by this immediate ordinary local profile; those rows do not claim Apache delayed-request behavior.

The supplement executes four `getErrorResponse` errors per API version against duplicate partitions and empty topic rows, with throttle42. These actual global error envelopes preserve the original request shape. They are kept under `apache_global_error_helpers` and are not substituted for normal map responses. Positive requests/responses round-trip through the actual SDK and must consume all bytes. Truncated requests fail the actual Apache parser. One trailing zero is accepted by Apache with one byte remaining; the local handler deliberately rejects it. That acceptance difference is recorded, with null response goldens for all six structural cases. Version2 unknown tags exercise normal skip behavior at request, topic and partition levels.

The runner verifies official distribution SHA512, source/archive/client JAR pins and embedded commit properties, retains selected upstream sources with LICENSE/NOTICE and per-file hashes, strictly compiles the same Java source against every release, then runs two separate output replays. It validates binary hashes, manifests, TSV identities, header versions, parse outcomes and exact replay/cross-release bytes. The matrix has 363 declared cases, 345 response frames and 18 local rejections; 1488 actual serializer/parser/helper checks and 72 actual helper executions across six replays. Source-only static policy declarations are not counted as broker runtime or durability assertions.

Run from the repository root using fresh scratch/output directories:

```sh
python3 docs/evidence/broker/KL11-10/oracle/apache/wire/prepare-and-run.py \
  --work /workspace/work/retention-apache/wire-reproduction \
  --output /workspace/work/retention-apache/wire-reproduction-results
```

Both compiler and execution JVMs use a 128 MiB heap and CPU affinity0–2,4. No source API adaptations or rebuilt Apache classes are needed. The ordinary profile remains single-node and nontransactional; production retention, fault/restart, authorization and network interoperability validation are separate.
