# Authenticated listener contract

This card remains in progress until the source-pinned wire, live-client and complete QA gates finish. The credential foundation at `1b4e0205565c552c28795b9ce595e1a83719af8b` is a separately verified component, not full listener qualification.

An optional listener profile supplies a durable credential store, an exact administrator principal allowlist, bounded parsing/admission settings and its actual installed API advertisement. The ordinary plaintext/TLS constructors and Handler trait keep their existing behavior. Each accepted socket owns its SASL state and absolute admission deadline; there is no address-keyed authentication map. A typed redacted Peer identity reaches application handlers only after proof verification. The explicit plaintext profile accepts SCRAM only. PLAIN requires a successfully established TLS connection. TLS identity and SASL identity remain separate.

Handshake17 supports classic v0/v1. Only negotiated v0 enters length-prefixed raw SASL token mode; v1 requires Authenticate36, classic v0/v1 or flexible v2. ApiVersions18 is available before handshake and in framed negotiation/authenticated states. Wrong state, wrong proof, unknown mechanism, malformed wire, exhausted control rounds/bytes or deadlines are terminal for that socket. Authenticate v1/v2 reports lifetime 0; KIP368 reauthentication remains KL11-71. No application frame is dispatched before successful authentication. A poisoned/stopped store blocks subsequent requests and fresh identity publication.

Original wire frames are owned zeroizing buffers, including partial reads and cancelled handler futures. Their Debug is redacted. PLAIN copies and imported admin SaltedPassword copies use owned zeroizing Secret. Verifier/key scratch lifetime limits remain those qualified in KL11-66; no complete stack, compiler/register or all cryptographic temporary erasure claim is made. Passwords retain Kafka raw UTF8 behavior; SCRAM usernames match the pinned ASCII SASLNAME parser, while PLAIN usernames can be UTF8. This is not general SASLprep conformance.

Describe50v0 and Alter51v0 require an exact authenticated administrator name, with an empty allowlist denying everyone. The listener uses only Store; the mutable pure mechanism Service never escapes it. Describe returns names, algorithms and iteration counts, never salts or keys. Independent execution of actual Apache ScramImage/ScramControlManager in all three pinned releases establishes duplicate policy: one Describe result per unique name, error 92 for repeated names; Alter rejects any second change for a name, including different algorithms, with error 92. Programmatic trusted bootstrap can still import both algorithms atomically in one Store mutation. Wire mutations remain per-user durable operations; a multi-user request can have independently successful and failed user results.

The configured store bounds request admission, retained entries, file bytes, replayed bytes and live verifier cardinality. A serialized blocking actor validates and prepares a whole candidate map/Arc, acquires the failfast generation write guard, synchronizes one atomic per-user journal record, then publishes without an intervening allocation or await. Authentication returns Busy while that actor holds the write guard. Queued cancelled mutations are skipped; a started mutation completes and synchronizes even when its caller/socket disappears. Lost acknowledgement or write/sync failure has an ambiguous disk outcome, resolved by reopening. I/O/corruption poisons new authentication/admin admission. Capacity failure preserves the last confirmed generation and reports a non-success outcome. Wire Busy/capacity uses local error 89; this bounded-overload choice is explicitly a local policy.

The journal persists only salt, iteration count, StoredKey and ServerKey. SaltedPassword and plaintext are never written. Recovery validates complete records and bounded replay before publishing any state, repairs only an incomplete final journal tail and reports the repair. Unix credential files must be regular, non-symlink and inaccessible to group/other users. Paths and parent directories are trusted configuration; no hostile directory race defense, cross-process locking, encryption at rest or malicious-writer authentication is claimed. Other platforms fail closed until equivalent ACL policy exists. File/hardware synchronization guarantees still apply. An admitted blocking file synchronization cannot be preempted safely; shutdown joins it after actual completion rather than claiming a disk-time bound.

Local hardening rejects empty/short salts, wrong hash-output lengths, control-character/oversized identities, out-of-range iterations, oversized messages/counts and duplicate/nonincreasing tags. Complete known schemas are consumed. API51v0 additionally recognizes exactly one empty top-level tag byte after its canonical body: genuine librdkafka2.15 writes body tags in its admin encoder, then its FLEXVER finalizer appends a second empty block. Other tails, nonzero tails, multiple extra bytes and every other API retain strict whole-input enforcement. This bounded compatibility policy was added after an actual native request reached the listener and failed; both that run and the passing earlier Rust matrix remain retained. It does not transform, strip or fabricate native wire bytes. Actual pinned Apache controller methods accept some empty/short salt and SaltedPassword inputs, and generated Java prefix readers accept arbitrary tails; those broader behaviors are not adopted. Independent outcomes are retained under KL11-72. Fixed error diagnostics redact input and paths; null versus empty success strings follow the authentic generated response defaults where checked by goldens.

Post-proof original frame allocation follows the configured transport request ceiling because the API key occurs inside the payload. The smaller control ceiling is enforced for APIs17/36/50/51 before header parsing, field copies or work admission; ApiVersions applies the same ceiling in its handler. Preauth frame allocation is capped before reserve from the length prefix.

Default preauth ceilings are 10 seconds, 64 KiB including length prefixes, 16 KiB per control frame and 8 requests/tokens. Default admin parsing permits 64 entries and 32 tags per block. Authentication and credential-store pools retain their configured whole-generation/admitted work caps. Resource ceilings bound owned work/buffers, excluding allocator, socket, executor and caller-retained overhead. A handler can allocate additional application memory according to its separate contract.
