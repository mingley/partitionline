The peers use genuine public producer, consumer and admin APIs. `CompactionPeer.java` is compiled unchanged against official Apache clients4.1.2,4.2.1 and4.3.1; `compaction-native.c` uses the pinned librdkafka2.15.0 header and shared library; the standalone `rust-adopter` uses the public partitionline crate from the same immutable source archive as the broker. No seed record is sent by a hand-built Produce request.

Every producer sends the same three scenarios, one acknowledged and flushed record at a time, with idempotence disabled and compression `none`. The three ordered headers are `d=a`, `d=null`, and `e=empty`. Timestamps include a nonmonotonic sequence. The mixed scenario exercises duplicate keys, null keys, tombstones, and a non-null empty key/value; the all-removed scenario becomes an empty cleaned prefix; the null-key-only prefix is removed. One final active record in each topic stays protected. In the first two scenarios its key is `a`, also present in the sealed prefix: including active records in the round's latest-key map would wrongly remove a retained sealed record and fail the public read assertions. Null keys are admitted by the declared ordinary broker profile before explicit cleaning; this does not establish Apache compact-topic Produce admission behavior.

The local test operator is separate from the Kafka wire profile. The runner atomically renames exactly28bytes (`topic UUID16`, `partition i32BE`, `clock i64BE`) to `compact-request`, and accepts the `compact-result` JSON only after the actor returns durable completion. First cleaning is at2000 with retention1000;2999 preserves the horizon and3000 expires tombstones at equality. The operator uses actual topic UUIDs obtained through public Admin descriptions. Five bounded server sessions use the same catalog/partition state; each stops and retains a bounded complete state snapshot before the next process opens it.

Each of the five reader implementations reads every producer's topics, seeking from0, from an interior gap, and from the former end offset. They compare exact topic/partition/offset/time/key/value/ordered header fields and require the public position to reach the preserved LEO. The runner separately compares the actual public histories across readers and producer implementations, preserves topic UUIDs through cleaning/restart, then requires genuine appends at the former end. The declared full lane has160peer jobs,45operator calls and15topics; all four broker/compiler feature lanes require fresh journals and actual results.

Public consumers expose records and positions. They do not expose the61byte empty-batch header or every removed journal extent. Those byte/extent guarantees remain owned by the separate Apache component and raw storage/wire proofs; a successful consumer receipt is not substituted for either. Ordinary RF1/manual assignment is the scope. Transactions, control batches, idempotent producer state, replicated ISR safety and consumer-group coordination are outside this proof.

`build-java.py` and `build-native.py` strict-compile only the peer sources and retain actual compiler commands, logs, executable hashes and pinned upstream dependencies. `build-rust.py` uses explicit work homes, offline locked builds, strict Clippy and formatting; its source-root must be an independently verified full Git archive. The standalone lock reuses the closed KL11-10 peer registry/checksum/dependency graph, changing only the standalone package name. No accepted Rust runtime proof exists until its actual locked build passes on the selected source/toolchain/feature lane. `run-live.py` verifies source/build/executable bindings before starting any broker and retains all partial/failing outcomes.

Preparation and final runtime results stay distinct. `development/formatter-environment-attempt-1/` preserves an unexpected wrong-home rustup ENOSPC setup failure and the exact shared-download cleanup receipt. No broker/runtime conclusion follows from it. Java/native strict preparation passed initially; Rust Cargo and all live runs await the parent's compiler lease and exact pushed compaction core source.
