# Local metadata/admin contract

Reviewed before implementation against the exact Apache 4.1.2, 4.2.1 and 4.3.1 source pins in the broker upstream inventory. The request/response schemas for these APIs are identical across those releases.

The composed router supports Metadata 0–13, ApiVersions 0–4, CreateTopics 2–4 and DeleteTopics 1–6. The standalone ApiVersions handler continues to advertise only API18. CreateTopics 5–7 remain unavailable: their config-result fields are not silently fabricated. Nonempty topic config overrides return INVALID_CONFIG. This foundation exposes a configured single node with RF1, logical partition leaders/ISR on that node, no offline replicas, automatic topic creation disabled and no authorizer. It does not advertise Produce or Fetch, nor claim replication or production qualification.

Metadata v0 empty topics means all; v1+ null means all and empty means none. UUID request targets are accepted only in v12+. If any nonzero UUID is present, Apache's broker uses the UUID set rather than mixing named targets. Name and UUID duplicates collapse to one result. Unknown IDs use UNKNOWN_TOPIC_ID and nullable names. A v12+ selector with null name and zero UUID is rejected after complete parsing: it cannot yield a response with neither identity field. Apache schema readers accept that shape; the pinned Topic.validate(null) component throws, so this close policy is an explicit local restriction rather than a fabricated upstream response. Classic/flexible schemas, header versions, v8–10 cluster authorization operations, v8+ topic operations and the v13 top-level error are explicitly encoded.

CreateTopics accepts automatic positive partition counts/RF1 and, since v4, -1 defaults; manual assignments must use both -1 fields and consecutive indices containing only this node. Invalid names, collisions, reserved metadata name, existing names, duplicate batch names, invalid assignments, unsupported overrides and local budgets receive per-topic errors. Duplicate batch names collapse to one INVALID_REQUEST result, as in ControllerApis. Validate-only performs validation without journal writes or ID allocation. Each topic operation is independently atomic; a multi-topic Kafka request is not a transaction.

DeleteTopics v6 accepts either a name or a nonzero UUID, rejects both/neither, collapses duplicates, and rejects aliases that resolve to an already supplied UUID. Success tombstones identities permanently. Names may be reused with fresh RFC4122 version4 identities generated through the approved getrandom0.4.3 dependency with bounded collision retries. Tombstones never revive.

A single bounded spawn_blocking storage actor exclusively owns Catalog. Startup/replay, append/sync and shutdown never block a Tokio executor thread. Bounded queue admission uses try_send. A canceled queued request is skipped before mutation; cancellation during a write or sync cannot retract an admitted durable operation and its outcome is ambiguous until metadata lookup/restart. Shutdown rejects new admission, stops before each next operation, drains pending replies and joins the actor; a canceled shutdown future can be retried. Drop requests stop but does not synchronously join. Poisoned catalog state is never served as current metadata. The journal remains the custom process-local catalog format described in KL11-59.

All request bodies are structurally parsed and bounded before mutation, including trailing bytes. After the first native C live failure, an independently captured/source-confirmed librdkafka2.15 defect received one read-only exception: flexible Metadata null/all-topics requests may carry exactly three zero tail bytes, as Apache parsers consume the canonical fields and ignore that tail. Named/empty selectors, classic Metadata and all other trailing bytes still fail; Create/Delete never admit a tail. Responses reserve their bounded maximum before mutations. The actor checks client timeout and cancellation before each operation. A timeout observed after a commit can return REQUEST_TIMED_OUT while retaining the commit; it is an explicitly ambiguous client outcome.
