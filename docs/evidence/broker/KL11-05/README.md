# Persistent single-node Metadata/admin handlers

The composed router implements Metadata0–13, ApiVersions0–4, CreateTopics2–4 and DeleteTopics1–6. The standalone ApiVersions handler still advertises only18/0–4. CreateTopics is explicitly partial against Apache's2–7 range: versions5–7 are unavailable, and nonempty config overrides return INVALID_CONFIG. The implementation registry and feature verifier reject inflated version/qualification claims.

The node endpoint and stable cluster ID are operator-provided. Every logical partition reports this single node as leader and sole replica/ISR, epoch0, with no offline replicas. Automatic topic creation is disabled and there is no authorizer. No Produce/Fetch support, physical partition storage, replication or production qualification is implied by these handlers.

Catalog startup/replay and append/sync run on one bounded spawn_blocking actor, never a Tokio executor thread. The queue is bounded in count and aggregate maximum request bytes (512MiB). All bodies are parsed before any mutation, and responses reserve their maximum bounded capacity before mutations. A canceled queued request is skipped. Cancellation or timeout after admission to a write can lose its receipt while retaining the durable operation; reconnect/look up or restart to resolve it. Each topic operation is independently atomic, rather than a multi-topic transaction. Poisoned catalog state is not served as current metadata. Stop rejects admission, drains pending replies and joins; a canceled shutdown can be retried, and a failed actor join remains failed on retry. Drop requests stop without synchronously joining.

Tombstones permanently reserve old identities; recreating a name gets a fresh ID.
