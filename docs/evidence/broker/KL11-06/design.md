# Ordinary Produce and storage ownership

Reviewed before code against pinned Apache 4.1.2/4.2.1/4.3.1 schemas and the independent KL11-68 proposal. Produce versions3–13 use names through12, UUIDs from13 and flexible framing from9. Exactly one magic2 batch per partition is accepted, matching actual ProduceRequest.validateRecords. Zstandard is unavailable before7. Ordinary producer sentinels, nontransactional records and CreateTime are the declared profile; codec activation follows optional KL11-67 rather than adding a default dependency. Error mappings distinguish independent request-component results from explicit local profile restrictions.

The metadata router's existing exclusive blocking actor also owns an optional bounded partition registry. Metadata-only startup retains the prior four-entry advertisement. An explicitly configured data router admits Produce and advertises API0/3–13 after its contract passes. Catalog lookup, delete and append serialize in one actor; topic identities never race an independent catalog owner. Storage names derive only from a stable UUID and validated nonnegative partition index, never topic names. Deleted identities' logs remain bounded retained history; recreation gets a new identity and cannot expose old data. Startup rejects unknown, malformed, duplicate or nonregular directory entries and validates every persisted batch through Partition recovery.

Limits bound queued input bytes, request topics/partitions, responses, normalized retained work, active/historical stores and FDs. Journal limits bound each file/index; configuration also checks worst-case aggregate disk and index envelopes. One actor serializes codec workspace and assigned-batch copies. These accounting limits exclude allocator bookkeeping and caller-retained outputs; they are not an RSS assertion.

Every request is fully structurally parsed before mutation; bounded result/response storage and valid normalized work are reserved before append. A per-partition input is one atomic fsynced entry; different partitions in one request are not a transaction. Kafka's ordinary leader epoch is set to local epoch0 outside CRC-protected bytes. Success returns exact base offsets after local sync. acks1 and -1 share local durable storage because the declared RF1 ISR contains only this node; no replicated guarantee is inferred. acks0 success returns no transport bytes while keeping the connection open; any partition error closes the connection, following pinned KafkaApis.

Queued canceled jobs are skipped. Cancellation, timeout or shutdown during an admitted append/sync can leave a committed operation without its receipt; ordinary producer retries can duplicate data and require readback/restart to resolve ambiguity. Poisoned storage cannot fabricate success. Stop/drain/join and retryable canceled shutdown reuse the metadata lifecycle. No blocking filesystem or codec work runs on a Tokio executor thread.

Actual native Magic2 Produce qualification waits for a real advertised Fetch>=4 handler because pinned librdkafka's feature negotiation requires it. No fake Fetch range is advertised to bypass that condition. Independent raw Java requests qualify every supported Produce version first; wire Fetch/ListOffsets, idempotence, transactions, replication, retention, security and production qualification remain separate cards.
